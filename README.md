How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?

- Writing maintainable code comes down to a few consistent habits: breaking functionality into small, single-purpose methods like separate create, read, update, and delete functions rather than one giant function handling everything, using clear and consistent naming, and adding comments that explain why something is done. There are many advantages to applying these practices, for example by wrapping every MongoDB operation inside a dedicated class with straightforward methods (create(), read(), update(), delete()), the rest of the application never needed to know MongoDB's underlying query syntax at all. This practice promotes reusability, testability, and reduces duplicate code. Additionally, in reference to future use cases for the CRUD module, since it's separate from any specific interface, it could be reused as the backend for a completely different front end.

How do you approach a problem as a computer scientist? Consider how you approached the database or dashboard requirements that Grazioso Salvare requested. How did your approach to this project differ from previous assignments in other courses? What techniques or strategies would you use in the future to create databases to meet other client requests?

- The core approach is to break a large, ambiguous problem into smaller, well-defined pieces, then solve and verify each piece before combining them. For Grazioso Salvare's requirements, that meant editing code to account for dashboard branding, creating functionality for dashboard widgets (data table, geolocation chart, and an optional chart), and enabling interactive filtering capabilities on the data table. Theses requirements were addressed incrementally and tested continuously to verify that each addition functioned properly. Unlike a lot of earlier coursework, this project required designing an entire system architecture, it involved the development of separate components (database, CRUD module, interactive UI, and visualizations), enabling communication between layers, and ensuring a change in one layer wouldn't disrupt another. Strategies like building and understanding the data layer before working on the interface layer, translating requirements precisely, and the modularization of different application layers can be used in future projects

What do computer scientists do, and why does it matter? How would your work on this type of project help a company, like Grazioso Salvare, to do their work better?

- Computer scientists solve problems by designing systems that take raw information and turn it into something people can actually use, whether that's developing systems to store data reliably, process it efficiently, or present it in a way that's clear and actionable. It matters because the systems/tools we build make real-world work faster, more accurate, and less dependent on slower, or more error-prone processes. In Grazioso Salvare's case, identifying which animals in Austin Animal Center's outcome data were good candidates for search-and-rescue training would have meant manually sifting through thousands of records. By creating a system that automates the search criteria, and makes the dataset visually accessible, it transforms an arduous task into a process that's efficient, easily repeatable, scalable with the dataset.
